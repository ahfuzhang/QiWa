
# Task 的哪些方法会阻塞物理线程的，请全部帮我列出来。

核心原则：

凡是“同步等待 Task 结果”的 API，都会阻塞物理线程。  
只有使用 `await` 的，才不会阻塞物理线程。

---

## 一、一定会阻塞物理线程的 Task API

### 1. Task.Wait()

```csharp
task.Wait();
```

- 阻塞当前 OS 线程  
- 直到 task 完成或抛异常  
- 内部是线程级等待（WaitHandle）

---

### 2. Task.Wait(TimeSpan timeout)  
### 3. Task.Wait(int millisecondsTimeout)

```csharp
task.Wait(5000);
```

- 阻塞线程  
- 最多等待指定时间  
- 返回 bool，表示是否完成

---

### 4. Task<T>.Result

```csharp
var x = task.Result;
```

- 如果 task 未完成：  
  - 阻塞当前线程  
  - 等待完成或异常  
- 等价于 `Wait()` + 取结果

---

### 5. Task.GetAwaiter().GetResult()

```csharp
task.GetAwaiter().GetResult();
```

- 阻塞线程  
- 与 `.Result` 本质一样  
- 区别在于异常包装方式不同

---

### 6. Task.WaitAll(...)

```csharp
Task.WaitAll(task1, task2);
```

- 阻塞线程  
- 等待所有 task 完成

---

### 7. Task.WaitAny(...)

```csharp
Task.WaitAny(task1, task2);
```

- 阻塞线程  
- 等待任意一个完成

---

## 二、容易被忽视，但同样会阻塞的写法

### 8. 通过 WaitHandle

```csharp
task.WaitHandle.WaitOne();
```

- 直接阻塞线程  
- 操作系统级等待

---

### 9. 在同步代码中强行等待异步

```csharp
SomeAsync().Wait();
SomeAsync().Result;
SomeAsync().GetAwaiter().GetResult();
```

这三种写法本质相同，都会阻塞当前物理线程。

---

## 三、不会阻塞物理线程的 Task API

以下写法是 async 安全的：

```csharp
await task;
await Task.WhenAll(tasks);
await Task.WhenAny(tasks);
await Task.Delay(...);
await Task.Yield();
```

原因：

- 不占用线程  
- 只是挂起 async 状态机  
- 线程立即还给线程池

---

## 四、对照表

| API                               | 是否阻塞物理线程 |
|----------------------------------|------------------|
| task.Wait()                      | 是               |
| task.Wait(timeout)               | 是               |
| task.Result                      | 是               |
| task.GetAwaiter().GetResult()    | 是               |
| Task.WaitAll(...)                | 是               |
| Task.WaitAny(...)                | 是               |
| task.WaitHandle.WaitOne()        | 是               |
| await task                       | 否               |
| await Task.WhenAll(...)          | 否               |
| await Task.WhenAny(...)          | 否               |

---

## 五、记忆法则

凡是带：

- Wait  
- Result  
- GetResult  

的等待方式，都会阻塞物理线程。

只有使用：

```csharp
await
```

才是不阻塞线程的等待方式。

---

## 六、工程级铁律

在 async 代码中遵守：

- 只要能 await，就绝不用：  
  - .Wait()  
  - .Result  
  - .GetAwaiter().GetResult()  
  - WaitAll / WaitAny  

否则极易导致：

- 线程池耗尽  
- 死锁  
- 吞吐量急剧下降  
- Web 服务请求卡死

# 在不阻塞物理线程的情况下，为新建的 Task 设定运行超时

目标：
在一个 Task（或 async 方法）中创建另一个 Task，并为其设置“运行超时”，同时**不阻塞物理线程**。

核心原则：
- 不使用 `.Wait()`、`.Result`、`WaitAll/WaitAny` 等同步等待
- 使用 `await`、`Task.WhenAny`、`CancellationTokenSource` 等异步原语
- 取消必须是“协作式”的（Task 本身无法被强制杀死）

---

## 方案一：等待层超时（Task.WhenAny + Task.Delay）

适用场景：
- Task2 不支持取消
- 只需要“放弃等待”，不需要强制停止 Task2

```csharp
async Task Task1()
{
    var task2 = Task2();

    var timeout = Task.Delay(TimeSpan.FromSeconds(5));
    var finished = await Task.WhenAny(task2, timeout);

    if (finished == timeout)
        throw new TimeoutException("Task2 timeout");

    await task2; // 这里 task2 已完成
}
```

特点：
- 不阻塞物理线程
- Task2 超时后仍会在后台继续运行
- 简单、通用

---

## 方案二：真正终止任务（CancellationTokenSource + 超时）

适用场景：
- Task2 支持 CancellationToken
- 希望在超时时真正停止执行

### Task1：创建带超时的取消源

```csharp
async Task Task1()
{
    using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(5));
    await Task2(cts.Token);
}
```

### Task2：配合取消

```csharp
async Task Task2(CancellationToken token)
{
    while (true)
    {
        token.ThrowIfCancellationRequested();
        await DoWorkAsync(token);
    }
}
```

特点：
- 不阻塞物理线程
- 超时后真正终止任务
- 需要 Task2 协作支持取消

---

## 方案三：等待层超时 + 取消（组合方式）

适用场景：
- Task2 支持取消
- 既想超时控制，又想明确处理超时逻辑

```csharp
async Task Task1()
{
    using var cts = new CancellationTokenSource();
    var task2 = Task2(cts.Token);

    var timeout = Task.Delay(TimeSpan.FromSeconds(5));
    var finished = await Task.WhenAny(task2, timeout);

    if (finished == timeout)
    {
        cts.Cancel(); // 请求 Task2 停止
        throw new TimeoutException();
    }

    await task2;
}
```

---

## 方案四：使用 .NET 6+ 的 WaitAsync

.NET 6 以后，Task 自带异步超时等待方法：

```csharp
await task2.WaitAsync(TimeSpan.FromSeconds(5));
```

等价于：

```csharp
var finished = await Task.WhenAny(task2, Task.Delay(timeout));
if (finished != task2)
    throw new TimeoutException();
```

特点：
- 简洁
- 不阻塞线程
- 只控制“等待”，不强杀任务

---

## 不能做的事情

以下写法都会阻塞物理线程：

```csharp
task2.Wait(5000);
task2.Result;
Task.WaitAny(task2, Task.Delay(5000));
```

这些都会：
- 卡住 OS 线程
- 在 Web / 高并发场景导致线程池耗尽

---

## 选择指南

| 需求 | 推荐方案 |
|------|-----------|
| 只限制等待时间 | Task.WhenAny + Task.Delay |
| 真正终止任务 | CancellationTokenSource(timeout) |
| 两者都要 | WhenAny + Cancel |
| .NET 6+ 简洁写法 | task.WaitAsync(timeout) |
| Web / async 场景 | 只用 await，不用 Wait |

---

## 标准答案总结

要在不阻塞物理线程的情况下，为新创建的 Task 设置超时：

- 用 `await` 等待
- 用 `Task.WhenAny` 或 `WaitAsync` 做超时判断
- 若需要真正终止，使用 `CancellationTokenSource(timeout)`
- 永远不要用 `.Wait()` 或 `.Result`
